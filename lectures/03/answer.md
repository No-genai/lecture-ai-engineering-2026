# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：素のLLMは質問に対してモデルが持つ知識で回答する。エージェントは `search_glossary` で用語集を調べてから回答するため、「宿題の3レベル」のような講座固有の内容も用語集の定義に基づいて説明できる。回答の内容や表現はモデルによって異なる。
- `--trace` で見えたツール呼び出し（ツール名と引数）：`LoRAとQLoRAの違いは？` という質問では、`search_glossary` が用語を検索する。検索ツールは一度に用語を1つ受け取る説明なので、`LoRA` と `QLoRA` が別々の呼び出しになることがある。実際に表示されたツール名と引数は実行時の trace に合わせて記録する。
- 1つの質問での LLM 呼び出し回数（`requests`）：`LoRAとQLoRAの違いは？` を `gemini-3.5-flash-lite` で実行したときは 2回だった。1回目のモデル呼び出しで `LoRA` と `QLoRA` を用語集から検索するツール呼び出しを要求し、検索結果を受け取った後、2回目のモデル呼び出しで回答を作成した。ツール呼び出し数（`tool_calls`）も2回だった。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture)` を追加し、指定回の用語を用語集から集めて1つ選び、「用語の意味は？」という問題と定義を返すようにした。用語がない回ではメッセージを返す。docstring には「指定した回の用語から1つを選び、確認問題と答えを返す」ことと、「第2回の確認問題を出して」のような復習用の問題を求められたときに使うことを書いた。関数を `agent.tool_plain` で登録すると、この説明がモデルにツールの説明として渡される。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - [app/agent.py](app/agent.py) の `INSTRUCTIONS` を一度だけ変えて、同じ質問で `--trace` を比較した
  - [app/tools.py](app/tools.py) の `search_glossary` の docstring を変えて、同じ質問で `--trace` を比較した
  - どちらがモデルの呼び出し方により大きな影響を与えたかを確認した
- 結果：
  - 変更前の質問 `uv run python -m app.agent --trace "LoRAとQLoRAの違いは？"` では、`search_glossary` が `{'query': 'LoRA QLoRA'}` のようにまとめて呼ばれることがあった
  - A: `INSTRUCTIONS` の指示だけを弱めても、ツールの説明が残っているため挙動の変化はほとんど見られなかった
  - B: `search_glossary` の docstring を `query には、調べたい用語をいくつでもまとめて入れてよい` と書き換えると、モデルは複数語を 1 つの検索クエリとして扱うようになった
  - 実際の trace では `search_glossary({'query': 'LoRA QLoRA'})` が確認できたため、モデルの挙動はツール説明の影響を大きく受けることがわかった
- 気づき・疑問：
  - AIエージェントは「全体の指示」よりも「各ツールの説明文」を強く参照して、どのツールをどんな引数で呼ぶかを決めていると感じた
  - そのため、基礎宿題としては `INSTRUCTIONS` だけでなく、`docstring` を変える実験のほうが比較しやすい
  - 検索の粒度を変えると、回答の質や実行回数にも影響しそうなので、次は「1語ずつ検索する」場合と「まとめて検索する」場合の違いをさらに比較したい
